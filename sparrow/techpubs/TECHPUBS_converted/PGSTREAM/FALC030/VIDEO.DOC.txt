Video Documentation


We recommend that all screen output be done via the GEM VDI.  This technique allows an application to take advantage of higher resolutions and greater color  capabilities of new screen modes yet still function in more limited situations. We do however recognize that direct screen output is something that applications authors are going to want to do.  As a result we are documenting the screen memory organizations in all modes in Sparrow.

The 1, 2, 4 and 8 bit per pixel modes are arranged as they are in an  ST,STE or TT.  This organization consists of 16 bits of each plane in adjacent words until all planes are accounted for.

The 16 bit per pixel (true color) mode of Sparrow is organized as packed pixels.  Each 16 bit word contains all of the information for a pixel.

Since this mode is a true color mode there is no palette to convert the data into RGB information for the video system.  The information is encoded in each pixel as follows RRRRRGGGGGXBBBBB.  The least significant G bit is also used as an overlay bit (designated as X).  We suggest that this bit NOT be used in graphic data.

A video (_VDO) cookie (yet to be defined or implemented) will allow quick identification that you are on a machine that supports the video that you require.
